# Сервис управления рассылками

Учебный проект на Django: управление получателями, сообщениями и рассылками,
ручной запуск отправки, журнал попыток, статистика, роли и кеширование.

## Что реализовано

### Часть 1

- CRUD получателей, сообщений и рассылок.
- Модель рассылки: начало, окончание, сообщение, получатели.
- Статус вычисляется динамически: «Создана», «Запущена», «Завершена».
- Валидация: начало не может быть в прошлом, окончание позже начала.
- Запуск рассылки из карточки и командой `send_mailing`.
- Для каждого получателя вызывается `send_mail()`.
- Попытки сохраняются пакетом через `bulk_create(batch_size=100)`.
- На главной: всего рассылок, активных рассылок, уникальных получателей.

### Часть 2

- Регистрация с подтверждением email по ссылке.
- Вход, выход, восстановление пароля.
- Статистика успешных и неуспешных попыток.
- Роли «Пользователь» и «Менеджер».
- Пользователь управляет только своими объектами.
- Менеджер видит всё, блокирует пользователей и отключает рассылки,
  но не редактирует чужие данные.
- Серверное кеширование (LocMem) и клиентское (`Cache-Control`, ETag).

## Стек

- Python 3.13
- Django 6.1
- PostgreSQL 18
- python-dotenv

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Открой `http://127.0.0.1:8000/`.

### Демо-данные

`seed_demo` создаёт:

| Роль | Email | Пароль |
|---|---|---|
| Пользователь | `user@example.com` | `User12345!` |
| Менеджер | `manager@example.com` | `Manager12345!` |

Также создаются получатели, сообщение и три рассылки: активная, будущая
и завершённая с журналом попыток.

Повторный запуск с `--reset` пересоздаёт рассылки демо-пользователя.

## Почта

По умолчанию используется console backend: письма печатаются в терминал
`runserver` или в вывод команды. Это удобно для проверки: ссылка подтверждения
регистрации и ссылка восстановления пароля видны прямо в консоли.

Для реальной отправки достаточно раскомментировать SMTP-блок в `.env`:

```env
MAILER_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_HOST_USER=mailer@example.com
EMAIL_HOST_PASSWORD=change-me
EMAIL_USE_TLS=True
```

Настройка собрана в `MAILERS` — новом API Django 6.1.

## Проверка рассылки

1. Войти как `user@example.com`.
2. Открыть «Рассылки» → активную рассылку.
3. Нажать «Запустить рассылку» — письма появятся в консоли, в журнале
   появятся записи «Успешно».
4. Открыть будущую рассылку и нажать «Запустить» — появится ошибка
   «Рассылка ещё не началась».
5. То же из командной строки:

```bash
python manage.py send_mailing <id>
```

Команда завершится с ошибкой, если рассылка отключена или время вне окна.

## Роли

| Действие | Пользователь | Менеджер |
|---|---|---|
| Свои клиенты, сообщения, рассылки | CRUD | CRUD |
| Чужие клиенты и рассылки | — | просмотр |
| Редактирование чужих объектов | — | запрещено |
| Список пользователей | — | да |
| Блокировка пользователей | — | да |
| Отключение рассылок | — | да |
| Статистика | своя | по всем |

## Кеширование

- `CACHES` — LocMem, таймаут по умолчанию 300 секунд.
- Главная и итоги статистики кешируются на 60 секунд.
- Версия кеша хранится в `stats_version`; сигналы `post_save`/`post_delete`
  увеличивают её. Для `bulk_create` версия сбрасывается явно в сервисе.
- Клиентский кеш: главная и статистика — `private, max-age=60`; списки
  и карточки — `private, max-age=0, must-revalidate`; формы — `no-store`.
  `ConditionalGetMiddleware` добавляет ETag.

## Допущения

- PostgreSQL должен быть запущен; параметры подключения задаются в `.env`.
- Email получателя уникален глобально, как указано в задании.
  Поэтому двух пользователей с одинаковым email создать нельзя.
- Часовой пояс — `Asia/Yekaterinburg` (+05), чтобы время в
  `datetime-local` совпадало с локальным временем машины. При необходимости
  поменяй `TIME_ZONE` в `config/settings.py`.
- Пользователей не удаляют, а блокируют: удаление может конфликтовать
  с защитой сообщений, на которые ссылаются рассылки.
- Статус рассылки не хранится в БД, а вычисляется при каждом обращении.
